# 24 周 AI Agent 工程学习路线

> 时间预算：每周约 10 小时，总计约 240 小时。
> 主线：理解机制 → 手写最小实现 → 引入框架映射 → 工程化与作品集。

## Phase 1：Python 与 LLM 接口（第 1–4 周）

**核心问题：** 一次模型调用到底发生了什么？

- Python 工程基础：虚拟环境、类型标注、日志、测试。
- HTTP、JSON、环境变量与密钥管理。
- Chat message、token、上下文窗口、采样参数。
- 结构化输出、工具调用契约与基础安全边界。

**阶段产出：** 一个 Python CLI 助手；每次调用能记录输入、输出、耗时、token 与估算成本。

## Phase 2：手写单 Agent（第 5–10 周）

**核心问题：** Agent 不是“提示词”，而是如何运行的循环？

- ReAct / plan-act-observe 循环与终止条件。
- 工具注册表、参数校验、权限边界和错误恢复。
- 短期记忆、状态持久化、重试与幂等。
- 评估样例集与轨迹调试。

**阶段产出：** 不依赖 Agent 框架的单 Agent：可调用多个受控工具、可恢复、可观察。

## Phase 3：RAG 与知识系统（第 11–16 周）

**核心问题：** 检索如何真正改善回答，而不是把文档塞进提示词？

- 文档清洗、分块、embedding 与向量检索。
- 混合检索、重排、引用与上下文压缩。
- 召回、忠实度、答案质量的离线评估。
- 知识更新、权限过滤、注入内容隔离。

**阶段产出：** 带引用和评估集的 RAG 服务。

## Phase 4：工作流与框架映射（第 17–19 周）

**核心问题：** 何时应使用确定性工作流，何时允许模型决策？

- 把前述 Agent 映射为显式状态图。
- 分支、循环、检查点、人类审批与恢复。
- 以 LangGraph 为代表的框架：只学习它如何表达已理解的概念。

**阶段产出：** 可恢复的 Agent 工作流，并说明每个节点的状态契约。

## Phase 5：多 Agent 系统（第 20–21 周）

**核心问题：** 多 Agent 的价值来自分工，而不是角色数量。

- 职责划分、共享状态与通信协议。
- 委派阈值、预算、超时、冲突和降级。
- Supervisor、router 与 artifact-driven collaboration。

**阶段产出：** 一个有单 Agent 基线对照的协作系统，包含失败降级策略。

## Phase 6：生产化与作品集（第 22–24 周）

**核心问题：** 如何让 Agent 在真实环境中可控地运行？

- tracing、指标、成本预算、限流与访问控制。
- 线上评估、回归集、提示词与工具版本管理。
- Docker 部署、API 服务与前端交互界面。
- 项目复盘：设计取舍、故障案例与下一步迭代。

**阶段产出：** 一个可部署的端到端项目、架构图、评估报告和技术文章。
