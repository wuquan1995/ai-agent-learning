# Phase 1 任务看板：Python 与 LLM 接口

每周保持同一节奏：**2 小时原理阅读 + 2 小时编码实验 + 1 小时复盘**。完成后将对应复选框勾选，并在周复盘中记录问题和证据。

## Week 1：Python 工程环境

- [ ] 阅读：Python 虚拟环境、包管理、类型标注与日志的作用。
- [ ] 实现：创建 `uv` 或 `venv` 环境；编写一个带类型标注与日志的 CLI 程序。
- [ ] 复盘：记录 Node.js 与 Python 的依赖、异常处理和测试体验差异。
- **完成标准：** `python -m` 可运行 CLI，并输出结构化日志。

## Week 2：HTTP、JSON 与密钥边界

- [ ] 阅读：HTTP 请求生命周期、状态码、超时、重试与 JSON 编解码。
- [ ] 实现：写一个 API 客户端，读取环境变量中的 token；模拟超时和非 2xx 响应。
- [ ] 复盘：列出密钥不能进入代码、日志、提示词和 Git 的原因。
- **完成标准：** 客户端可区分网络错误、认证错误和服务错误。

## Week 3：Chat Message 与上下文

- [ ] 阅读：system、user、assistant、tool message 的语义；上下文窗口与 token。
- [ ] 实现：保存一次多轮会话为 JSON，并实现 token/字符数的粗略统计。
- [ ] 复盘：解释“历史消息”与“长期记忆”为什么不是同一个概念。
- **完成标准：** 能打印消息序列、长度统计和截断策略。

## Week 4：调用观测与成本

- [ ] 阅读：采样参数、延迟、输入/输出 token 与成本的关系。
- [ ] 实现：为模型调用封装计时、请求 ID、token 用量和估算成本日志。
- [ ] 复盘：为一个 Agent 任务定义延迟与成本预算。
- **完成标准：** 每次调用都生成可检索的一条观测记录。

## Week 5：结构化输出

- [ ] 阅读：JSON Schema、Pydantic 模型、解析失败与重试边界。
- [ ] 实现：要求模型输出一个任务计划 JSON；使用 Pydantic 校验并展示校验错误。
- [ ] 复盘：比较“自然语言解析”与“受约束结构化输出”的风险。
- **完成标准：** 不合法结果不会进入后续业务逻辑。

## Week 6：工具调用契约

- [ ] 阅读：函数签名、参数 schema、工具结果和副作用。
- [ ] 实现：注册两个无副作用工具（例如计算器、时间转换），并执行参数校验。
- [ ] 复盘：为每个工具标记读取、写入和外部副作用等级。
- **完成标准：** 无效参数、工具异常和正常结果都能形成统一结果对象。

## Week 7：提示注入与信任边界

- [ ] 阅读：直接提示注入、间接提示注入、数据与指令的区别。
- [ ] 实现：准备包含恶意文本的测试资料；在代码中将外部内容明确标为不可信数据。
- [ ] 复盘：写下三条工具权限与敏感数据处理规则。
- **完成标准：** 测试用例不能借由外部文本触发未授权工具行为。

## Week 8：最小 CLI 助手

- [ ] 阅读：将模型、观测、结构化输出和工具边界组合成程序的方式。
- [ ] 实现：完成一个 CLI 助手，支持一项结构化任务和至少一个受控工具。
- [ ] 复盘：写一篇阶段总结：知道了什么、仍不确定什么、下一阶段要验证什么。
- **完成标准：** 提供可复现运行命令、示例输入输出和一次失败轨迹。
