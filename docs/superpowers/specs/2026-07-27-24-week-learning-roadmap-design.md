# 24 周 AI Agent 学习路线设计

## 目标

在 24 周、每周约 10 小时（总计约 240 小时）内，以原理优先的方式完成 AI Agent 工程转型，并产出一个可部署、可评估、可展示的端到端作品集项目。

## 不变原则

1. 先理解模型调用、状态、工具、检索、评估和恢复机制，再使用 Agent 框架。
2. 先建立单 Agent 的可观察性、测试和安全边界，再引入多 Agent。
3. Python 用于 Agent 运行时和服务侧；现有 TypeScript、Vue、React 能力用于最终产品界面。
4. 每周都必须留下代码、实验记录、评估证据或复盘，而非只完成课程观看。

## 每周时间分配

| 投入 | 用途 |
| ---: | --- |
| 3 小时 | 原理、官方文档、论文或源码阅读，并形成自己的解释 |
| 5 小时 | Python 实现、自动化测试和可复现实验 |
| 1 小时 | 构造评估样例、检查成本/延迟并记录失败案例 |
| 1 小时 | 周复盘、更新 GitHub 任务状态和下周计划 |

## 阶段设计

### Phase 1：Python 与 LLM 基础（Weeks 1–4）

建立虚拟环境、类型标注、日志、测试、HTTP/JSON、环境变量与密钥边界。理解 Chat message、token、上下文、采样参数、结构化输出和工具调用契约。

**产出：** 可观测 Python CLI 助手，记录请求、耗时、token 和估算成本。

### Phase 2：手写单 Agent（Weeks 5–10）

从零实现 plan-act-observe 循环、工具注册与参数校验、状态持久化、终止条件、错误恢复、重试与评估集；不使用 Agent 框架。

**产出：** 可调用多个受控工具、可恢复、可追踪的单 Agent。

### Phase 3：RAG 与知识系统（Weeks 11–16）

实现文档处理、分块、embedding、混合检索、重排、引用、上下文压缩、离线评估、更新与权限边界。

**产出：** 带引用和离线评估集的 RAG 服务。

### Phase 4：工作流与框架映射（Weeks 17–19）

把已手写的 Agent 映射为显式状态图，学习分支、循环、检查点、人类审批与恢复；此时再以 LangGraph 表达同样的状态与契约。

**产出：** 可检查点恢复、包含人工审批节点的 Agent 工作流。

### Phase 5：多 Agent 边界（Weeks 20–21）

比较单 Agent 与多 Agent 的成本和效果，设计职责、共享状态、委派阈值、预算、超时、冲突和降级。

**产出：** 有明确分工、单 Agent 基线对照和失败降级策略的协作系统。

### Phase 6：生产化与作品集（Weeks 22–24）

加入 FastAPI、Tracing、指标、成本控制、限流、评估回归、Docker 部署与前端交互界面。

**产出：** 一个可部署的端到端 Agent 产品；包含架构说明、评估报告、演示和技术复盘。
